# Локальная установка

## Требования

Go 1.26.7, Docker Engine с Compose v2, Linux, доступ к реестрам образов, свободные порты 8443, 8200, 8090 и 24224 на loopback. Выделите достаточно памяти для SQL, наблюдаемости и трёх агентов; начальный стенд рассчитан примерно на 4–6 ГиБ RAM. Для объёмных видео запас диска должен покрывать временную и издательскую копии, опубликованные данные, SQL и образы.

```sh
make build
bin/begomctl init --dir .local
docker compose config --quiet
docker compose --progress plain up -d --build
docker compose ps
```

Порядок запуска задан зависимостями: права каталогов → SQL/OpenBao → инициализация секретов → координатор → агенты/NGINX. Успешный `healthz` означает только работу процесса, `readyz` проверяет SQL, том, секреты и поколение диспетчера. После рестарта координатор некоторое время остаётся неготовым, пока действует защитный интервал C6.

После unseal инициализатор ждёт активного состояния OpenBao через `/v1/sys/health` до одной минуты: разблокированный Raft-узел ещё может оставаться standby с хранилищем только для чтения. Только после готовности создаются KV, политики и AppRole. Повторный запуск продолжает настройку с сохранёнными ключами; `PUT /sys/init` для уже инициализированного узла не повторяется. При истечении ожидания bootstrap завершается с ошибкой, а зависимые службы не запускаются.

Журналы передаются Fluent Bit через асинхронный драйвер `fluentd`. Режим Docker `non-blocking` ограничен буфером 4 МиБ на контейнер, очередь драйвера — 4096 событиями; локальный кэш ограничен тремя файлами по 10 МиБ. При переполнении сообщения могут теряться. Параметр `fluentd-write-timeout`, отсутствующий в Docker на первом GitHub runner, не используется; недоступность сборщика не должна блокировать приложение. Параметры режима и буфера описаны в [документации Docker](https://docs.docker.com/engine/logging/configure/#configure-the-delivery-mode-of-log-messages-from-container-to-log-driver).

Интерфейс доступен по `https://localhost:8443`. Имя — `admin`, пароль находится в `.local/client-password`. CA — `.local/secrets/ca.crt`. Приватные файлы не публикуются и не выводятся инициализатором. Не используйте отключение проверки TLS как настройку клиента.

`init` создаёт новую область и отказывается перезаписывать существующий профиль. Инициализатор прав работает только с сгенерированными каталогами; существующие опубликованные файлы рекурсивно не переназначаются. Агенты имеют разные UID и видят только свою временную область. Область `published` монтируется в NGINX только для чтения.

## Сервисы и доступ

| Адрес | Назначение |
|---|---|
| `https://localhost:8443` | приложение и административная Grafana под `/grafana/` |
| `https://localhost:8200` | OpenBao, только локальная эксплуатация |
| `http://127.0.0.1:8090` | управляемый тестовый донор |
| `127.0.0.1:24224` | Fluent Forward от Docker; не публичный интерфейс |
| приватная сеть Compose | PostgreSQL, mTLS API 8444, метрики, Loki, Prometheus, SSH агентов |

Файл `.local/bootstrap/bao-init.json` содержит материал восстановления локального OpenBao. В разработке используется одна доля; Linux-профиль создаёт пять долей с порогом три. После остановки OpenBao требуется unseal. Для локального профиля:

```sh
docker compose start openbao
docker compose run --rm --no-deps bootstrap
```

Сохраните материал восстановления отдельно от тома OpenBao. При потере единственного ответа первоначальной инициализации ключи нельзя восстановить из SQL или логов; не повторяйте инициализацию над существующим хранилищем и не удаляйте том автоматически.

Если прежняя версия bootstrap завершилась с `OpenBao bootstrap operation rejected: /v1/sys/mounts/secret`, а OpenBao сообщил `cannot write to readonly storage`, пересоберите приложение и повторите `docker compose up -d --build` для того же профиля. Используйте прежние `COMPOSE_PROJECT_NAME`, `BEGOM_STATE_DIR` и `COMPOSE_FILE`; данные и материал восстановления остаются на месте. В профиле Kinescope обязательно сохраняйте оба Compose-файла из команды ниже. Проверяйте результат через `docker compose ps -a`: `bootstrap` должен иметь `Exited (0)`, координатор и агенты — `healthy`.

Остановка без удаления данных:

```sh
docker compose down
```

`down -v` не является командой обычной эксплуатации: она удаляет SQL, секреты и копии. Локальное хранилище видео находится в каталоге профиля; SQL и инфраструктурные данные — в именованных томах проекта.

## Отдельные профили

Для второго стенда укажите отдельные имя проекта и каталог. Одновременно используемые профили должны иметь разные опубликованные порты и подсети; фиксированная исходная подсеть `172.30.69.0/24` предназначена для одного локального стенда.

```sh
bin/begomctl init --dir .local-test
export COMPOSE_PROJECT_NAME=begom-test
export BEGOM_STATE_DIR=./.local-test
docker compose up -d --build
```

CLI и тесты используют путь к `client.json`, Compose — `BEGOM_STATE_DIR`. Приёмочный драйвер учитывает `COMPOSE_PROJECT_NAME`.

## Kinescope

Создайте отдельный профиль и БД; числовые результаты mock не смешиваются с реальным донором.

```sh
bin/begomctl init --dir .local-kinescope --source kinescope
export COMPOSE_PROJECT_NAME=begom-kinescope
export BEGOM_STATE_DIR=./.local-kinescope
docker compose -f docker-compose.yml -f deploy/compose.kinescope.yml up -d --build
```

Этот профиль даёт агентам исходящий доступ и не запускает mock. Исходный общий предел — 1 RPS; это **настройка Begom**, а не подтверждённая квота Kinescope. Начинайте с небольшого разрешённого диапазона и согласуйте ограничения с владельцем сервиса. Проверяется каждый домен и IP, включая перенаправления. Не расширяйте allowlist на весь Интернет для устранения ошибки адаптера.

Обрабатываются числовые URL `https://kinescope.io/{id}` и их перенаправления на каноническую страницу. UUID-URL не является диапазоном. Публичный JSON `playerOptions` разбирается без выполнения JavaScript. Ссылка `downloadLink` означает наличие опубликованного владельцем маршрута скачивания; по нему выбирается лучший допустимый видеоasset. Отсутствие ссылки — `skipped`, 401/403 — `forbidden`. HLS/DASH, PDF и транскрипты учитываются отдельно и не скачиваются вместо видео. Это согласуется с [настройками скачивания в документации Kinescope](https://docs.kinescope.ru/videopleer-nastrojka-i-vstraivanie/kastomizatsiya-pleera/).

Пароли от Kinescope и административные токены не нужны. Страница неизвестного формата даёт диагностируемую ошибку; система не запускает браузерный JavaScript и не обходит ограничения.
