# Локальная установка v2

## Настоящий Kinescope

Нужны Linux, Go 1.26.7, Docker Engine с Compose, доступ к реестрам и запас 6–8 ГиБ RAM. Команды выполняются из корня репозитория:

```sh
bash deploy/local-v2.sh up
bash deploy/local-v2.sh status
```

Откройте **https://localhost:8445**. Имя — `admin`, пароль — `.local-v2-kinescope/client-password`, доверенный CA — `.local-v2-kinescope/secrets/ca.crt`. Скрипт не выводит пароли и ключи. Чистый профиль `begom-v2-kinescope` имеет отдельные SQL/инфраструктурные тома, каталог состояния и сеть `172.30.79.0/24`. Прежний профиль автоматически не удаляется и может продолжать работать на 8443.

Порты нового профиля: 8445 — всё приложение и Grafana; 8202 — локальный OpenBao; 24225 — локальный Fluent Forward. PostgreSQL, Prometheus, Loki, API агентов и оба SSH-порта доступны только внутри сетей Compose. Для Kinescope агенты имеют выход в сеть; mock-донор не запускается. Исходный общий предел — 1 RPS, это настройка Begom, а не утверждение о квоте сервиса.

Порядок запуска: права каталогов → SQL/OpenBao → bootstrap секретов → координатор → агенты и NGINX. Bootstrap ожидает активного OpenBao после unseal до одной минуты и сохраняет ключи при повторе. После рестарта C6 выдерживает интервал защиты прежнего поколения. `readyz` проверяет зависимости, `healthz` — только процесс.

## Работа

1. Создайте и запустите парсинг числового диапазона. Он сохраняет разрешённые метаданные, не загружая видео.
2. В «Каталоге для скачивания» выберите найденные материалы и создайте отдельное скачивание. Запустите его в «Заданиях».
3. Откройте «Видеогалерею» для просмотра и получения готовых файлов. Доступ коллегам выдаётся учётными записями и ACL заданий.

Внутренний OpenSSH 2223 и shell работают от `begom-shell` без sudo и эффективных capabilities. В Compose это среда контейнера выбранного агента. Служебный RPC 2222 имеет другую SSH-идентичность. Профиль создаёт обе пары ключей; приватный клиентский ключ терминала хранится в OpenBao. Веб-терминал не требует публикации SSH-портов.

## Управление и настройка

```sh
bash deploy/local-v2.sh logs
make acceptance  # два этапа на официальном Kinescope
bash deploy/local-v2.sh down
bash deploy/local-v2.sh up
```

`down` останавливает только выбранный проект, сохраняя тома. `init` создаёт новый профиль и не перезаписывает идентичности. API v2 требует чистого профиля: подключение базы с заданиями v1 отклоняется миграцией 005. Для отката сохраните старую версию приложения и соответствующий профиль.

Скрипт поддерживает переменные `BEGOM_V2_PROJECT`, `BEGOM_V2_STATE_DIR`, `BEGOM_WEB_PORT`, `BEGOM_BAO_PORT`, `BEGOM_LOG_PORT`, `BEGOM_CONTROL_SUBNET`, `BEGOM_PUBLIC_ORIGIN`. Задавайте их последовательно для всех команд одного профиля. Унаследованные `COMPOSE_PROJECT_NAME`, `BEGOM_STATE_DIR`, `COMPOSE_FILE` и `COMPOSE_PROFILES` старого стенда не выбирают профиль этого скрипта. Изменение внешнего адреса уже созданного стенда требует также изменения `public_origin` в конфиге координатора; для Grafana используется `<origin>/grafana/`. После этого пересоздайте соответствующие контейнеры.

## Изолированный стенд автоматических проверок

Только для испытаний используется управляемый донор. Отдельный профиль можно запустить одновременно с Kinescope:

```sh
export BEGOM_SOURCE=mock
export BEGOM_WEB_PORT=8446
export BEGOM_BAO_PORT=8203
export BEGOM_LOG_PORT=24226
export BEGOM_MOCK_PORT=8093
export BEGOM_CONTROL_SUBNET=172.30.89.0/24
bash deploy/local-v2.sh up
```

Он создаёт `.local-v2-mock` и `begom-v2-mock`; исходные настройки — три агента по 40 потоков, общий предел 80 RPS и 120 соединений. Общий локальный том является профилем разработки. Настоящие NFSv4/Kerberos и независимые узлы проверяются отдельно.

Для последующих тестовых команд дополнительно экспортируйте `COMPOSE_PROJECT_NAME=begom-v2-mock`, `BEGOM_STATE_DIR=./.local-v2-mock`, `COMPOSE_FILE=docker-compose.yml:deploy/compose.v2.yml`, `BEGOM_PUBLIC_ORIGIN=https://localhost:8446`. Приёмка останавливает только службы этого тестового проекта.

## Диагностика

Проверяйте `status` и журналы перед повторным запуском. Для одноразовых `permissions/bootstrap` нормален `Exited (0)`; координатор и три агента должны быть healthy. Не удаляйте каталог `.local*`, пока работают привязанные к нему контейнеры: SQL, секреты и идентичность тома должны соответствовать друг другу. Приватные ключи, пароли и `.part` не включайте в отчёты.
