# Руководство оператора

## Задание

После входа выберите серверы, диапазон, общие и индивидуальные потоки, размер блока, тайм-аут, повторы и условия остановки. Формы диапазона: пусто — `[0,∞)`, `N` — `[0,N]`, `[A,B]` и `[A,]`. Границы включаются. В API все идентификаторы передавайте десятичными строками; не преобразуйте их через JavaScript `Number`.

Индивидуальные потоки имеют приоритет над общими, но ограничиваются возможностями узла. Нулевые ограничения задания означают отсутствие дополнительного ограничения; глобальный предел донора остаётся обязательным. Частота HTTP не равна числу потоков. Малый RPS и ответы 429 увеличивают ожидание permit, а не создают новые соединения в обход C6.

Основные действия:

- **Запустить** — проверка доступности ресурсов и переход к выдаче блоков.
- **Пауза** — запрет новых блоков и новых ID в текущем блоке; уже начатые операции заканчиваются, остаток блока возвращается в очередь.
- **Продолжить** — новая `run_id`; подтверждённые результаты сохраняются.
- **Остановить** — немедленное прекращение права работы, сохранение подтверждённых контрольных точек.
- **Повторить ошибки** — выбрать `failed` результаты; подтверждённые файлы не переоткрываются. Для завершённого задания после выбора ошибок применяется явное продолжение.

`completed` означает завершённый проход, включая `not_found`, `skipped`, `forbidden` и окончательные ошибки. Для повторного полного прохода создайте новое задание. `max_items` ограничивает исходный эффективный диапазон и после создания не меняется; для раннего прекращения используйте остановку либо время завершения. `consecutive_missing` — явная эвристика владельца, а не доказательство конца внешнего каталога.

Контрольная точка — первый ID без подтверждённого финального результата. Поздние завершения больших ID её не перескакивают. Бесконечный диапазон создаётся лениво и исчерпывается на максимальном `uint64` без переполнения.

## Наблюдение и результаты

Карточка задания показывает состояние, диапазон, непрерывный прогресс, текущую скорость по пятисекундному окну, среднюю скорость прохода, скорость активных файлов, среднюю принятых байтов, объём, ошибки и приблизительное ETA. При неопределённой границе ETA не задаётся. Сеть, диск, CPU, RAM, swap, соединения и открытые файлы относятся к ОС узла. Показатели чужих заданий и названия загрузок фильтруются по ACL.

Страница серверов показывает heartbeat, версию, блок, измерение ресурсов, текущие ID и названия файлов, смещение и скорость. Возраст измерения свыше пяти секунд выделяется. Изменение потоков и лимитов вступает в силу для последующей работы. При уменьшении предела существующие соединения завершаются, новые разрешения ограничиваются новым значением.

В результатах доступны статус, метаданные, просмотр опубликованного видео, выбор ошибок и CSV/JSON. Экспорт потоковый; после сбоя JSON содержит `complete:false`, CSV — `incomplete_export`, а trailer — `X-Export-Complete:false`. Для согласованного неподвижного набора сначала дождитесь мягкой паузы. Источником выдачи остаётся готовый каталог: прямой путь к временной области и внутренний URI NGINX недоступны.

Журнал задания поддерживает время, сервер, статус и курсор HTTP API. Аудит предназначен администратору и содержит действия пользователей, доступ, публикацию и SSH-операции. Глобальные панели Grafana также доступны только администратору.

## Grafana

Войдите в Begom как администратор и нажмите **Grafana ↗**. На локальном стенде прямая ссылка — `https://localhost:8443/grafana/d/begom/begom`. Дополнительный вход и ручное создание источников данных не нужны. Панель **Begom — эксплуатация** также доступна через **Dashboards → Begom**. Корень `/grafana/` использует эту панель как домашнюю; настройка `default_home_dashboard_path` описана в [документации Grafana](https://grafana.com/docs/grafana/latest/setup-grafana/configure-grafana/#default_home_dashboard_path).

Справа сверху выберите период, например последние 15 минут, и обновление раз в секунду. При отсутствии заданий CPU, свободное место и доступность сервисов продолжают отображаться, а скорость загрузки и активные соединения равны нулю. Серия HTTP появляется после первых запросов к донору; до этого возможен `No data`. В локальном профиле панель доступности показывает 11 целей: координатор, три агента и инфраструктура; `1` означает успешный сбор метрик, `0` — ошибку сбора.

| Панель | Что проверять |
|---|---|
| Доступность сервисов | Нет ли недоступного процесса или ошибки соединения с его метриками |
| Активные HTTP-соединения / Допуски в очереди | Есть ли работа и ожидание общей квоты; очередь при ограничении RPS допустима |
| HTTP по классам и результатам | Проверки и загрузки, ответы 2xx/4xx/5xx и сетевые ошибки |
| Свободное место / CPU рабочих серверов | Ресурсы каждого агента; в локальном профиле агенты используют один компьютер |
| Скорость загрузки | Принятые байты в секунду по агентам |
| Журналы | Записи Loki за выбранный период; раскрывайте JSON-поля для поиска по `job_id` и `worker_id` |

Для самостоятельного поиска откройте **Explore**, выберите **Loki** и запрос `{service=~".+"} | json`. Для конкретного задания добавьте `| job_id="ID задания"`; `| worker_id="worker-1"` фильтрует сервер. Для метрик выберите **Prometheus**: `up` показывает доступность, `begom_worker_cpu_percent` — CPU. Данные о конкретном задании клиент смотрит в Begom с учётом ACL; инфраструктурная Grafana предназначена администратору.

## Выдача видео клиенту

1. Администратор открывает **Пользователи → Добавить пользователя**, задаёт имя, пароль и роль `viewer`. ID созданной записи отображается в списке пользователей.
2. В карточке нужного задания оператор с правом управления или администратор открывает **Доступ**, вводит ID пользователя, выбирает **Просмотр** и сохраняет. Одна роль `viewer` сама по себе не открывает чужие задания.
3. Клиент входит в Begom под своей учётной записью, открывает **Задания → Результаты** или находит задание через **Историю**. Фильтр `completed` оставляет успешно скачанные и опубликованные материалы.
4. **Смотреть** открывает встроенный проигрыватель; **Скачать** сохраняет файл на компьютер клиента. Для `skipped`, `not_found`, `forbidden` и `failed` видеофайла нет. JSON и CSV выгружают описание результатов, а не содержимое видео.

Ссылка на файл имеет вид `https://localhost:8443/api/files/FILE_ID/content`; `file_id` есть в JSON-экспорте результатов. При открытии ссылки нужны действующая сессия Begom и доступ к заданию. Ссылка не является анонимным публичным доступом. Файлы выдаёт NGINX после проверки координатором; подключать клиенту NAS или передавать внутренний URI `/_published/` не требуется.

Локальный Compose публикует интерфейс только на loopback компьютера со стендом. Чтобы работать с другого компьютера без изменения профиля, выполните на нём `ssh -N -L 8443:127.0.0.1:8443 USER@STAND_HOST`, затем откройте `https://localhost:8443` и доверьтесь CA стенда. Для общего сетевого адреса используйте Linux-профиль с настроенными DNS, `public_origin` и TLS из [инструкции установки](install-linux.md).

## Узлы и терминал

Администратор задаёт адрес, SSH-порт/пользователя, публичный host key, ссылку на секрет OpenBao, потоки, лимиты и пороги ресурсов. Пароль либо приватный SSH-ключ хранится в OpenBao, а не в форме. Каталог NAS должен совпадать с конфигурацией установленного агента. Сначала отключите узел от работы, затем измените проверенный mount и конфигурацию, перезапустите агент и включите узел. Смена пути инвалидирует прежнюю регистрацию.

При необходимости добавьте узел через API/интерфейс, выпустите его mTLS-идентичность и установите агент с отдельным NAS principal. Добавление записи в инвентарь само по себе не устанавливает сервер. Эталонный профиль разворачивает три узла; дополнительные узлы получают такие же изолированные идентичности.

Терминал поддерживает `help`, `status`, `resources`, `logs [1..1000]`, `start`, `stop`, `restart`. Это диагностический шлюз; произвольный shell, перенаправления, пайпы и forwarding запрещены. Обновление выполняется отдельной операцией по подписанному пакету. Сессия завершается через 15 минут либо после двух минут простоя. Если координатор прервал SSH-операцию до подтверждения, `outcome_unknown` требует проверки `status` и версии перед новым действием; автоматический повтор неизвестного рестарта не выполняется.

## Неисправности

| Симптом | Действие |
|---|---|
| Grafana: `502 Bad Gateway`, пустая страница или перезапуск | проверить OOM и `RestartCount` контейнера; профиль задаёт 1 ГиБ памяти, после изменения лимита контейнер нужно пересоздать, а не только перезапустить |
| `dispatcher_recovering` | дождаться drain; не запускать второй активный координатор |
| `stale_attempt` / `agent_session_lost` | проверить heartbeat, сертификат, регистрацию; старые результаты не форсировать |
| `storage_path_mismatch` | сверить путь NAS узла и инвентарь, не создавать локальную замену mount |
| `insufficient_storage` | освободить или расширить NAS, учесть общий SQL-резерв и копию издателя |
| `unsupported_page_schema` | сохранить безопасный пример формата и обновить адаптер; не выполнять JS страницы |
| `download_not_allowed` | штатный `skipped`, не искать потоковую альтернативу |
| 401/403 | сохранить `forbidden`, не обходить ограничение |
| 429 | уважать `Retry-After`, проверить общую квоту и панели C6 |
| `catalog_checksum_mismatch` | файл изъят из выдачи; восстановить из копии либо повторить ошибку после проверки источника |
| SQL/OpenBao/NAS недоступны | восстановить зависимость; не подтверждать результаты вручную и не сбрасывать поколение/квоту |

Не удаляйте вручную SQL-строки аренды, таблицы идемпотентности или готовые файлы для «ускорения» восстановления. Для проверки фактических действий используйте журнал и аудит с `job_id`, `chunk_id`, `attempt_id`, `external_id`, `request_id`.
