# Профиль реализации

Этот документ дополняет ЭП и ТП исполняемыми решениями. Обязательные требования остаются в ТЗ; результаты проверок — в отдельном протоколе.

## Процессы и модули

| Процесс | Исходники | Назначение |
|---|---|---|
| `coordinator` | `cmd/coordinator`, `internal/coordinator`, `db`, `dispatch`, `publication`, `auth` | API, задания, аренды, C6, публикация, интерфейс, аудит, управление узлами |
| `agent` | `cmd/agent`, `internal/agent`, `donor`, `target`, `storage`, `hostmetrics` | heartbeat, ограниченный пул, A4, адаптер, `.part`, SHA-256 |
| `begomctl` | `cmd/begomctl`, `bootstrap`, `acceptance`, `backup` | CLI, установка, пакеты, копии, восстановление, измерения |
| `mockdonor` | `cmd/mockdonor`, `internal/mockdonor` | Управляемые ответы и синтетическое видео, реальные счётчики запросов |
| `node-helper` | `cmd/node-helper`, `internal/nodecontrol` | Ограниченный SSH RPC/терминал; локальный supervisor либо systemd/sudo |

Веб-ресурсы встроены в бинарник через `embed`. Сборка фронтенда и внешний CDN не нужны. Воспроизводимые схемы API генерируются `go run ./tools/openapi`.

## Хранение

SQL содержит все таблицы §17 ТЗ и дополнительные таблицы ACL, сессий, идемпотентности, поколений, резервов, публикаций, SSH-операций и квот. `numeric(20,0)` и десятичные строки в JSON сохраняют весь диапазон `uint64`. `NULL next_id/frontier` обозначает исчерпание, включая максимальный идентификатор без переполнения.

На NAS находятся `.begom-volume`, `staging/WORKER/ATTEMPT/STAGE/`, закрытая `publishing/PUBLICATION/`, `published/SOURCE/ID/PUBLICATION/video` и карантин. Название видео не используется как имя каталога. SHA-256 и размер проверяются перед подтверждением. Архивируется первый принятый файл канонического материала; автоматическое версионирование заменённого содержимого под тем же каноническим ID не является отдельной функцией этой поставки.

Частичный файл продолжается в пределах действующей попытки при совпадении размера, SHA-256 префикса и HTTP validator. После смены попытки новая загрузка может начаться с нуля; каталог другого агента не заимствуется. Это сохраняет изоляцию временных областей. Старые неподтверждённые области удаляются оператором после проверки отсутствия аренды и публикации; автоматическая очистка неизвестных данных не выполняется.

## Квоты и доступность

Каждый HTTP hop, повтор и Range-запрос получает свой permit. Выдача равномерная, без накопления всплеска за время простоя; классы и воркеры обслуживаются по очереди. Бюджет дополнительно учитывает TTL и допустимую разницу часов. Поэтому фактическая скорость обычно ниже настроенного верхнего предела. RPS и параллелизм измеряются отдельно.

Перезапуск сначала получает SQL fence и выдерживает drain старого поколения. Подтверждения идемпотентны; память C6 может быть восстановлена повторным спросом. Серверы должны синхронизировать часы через chrony. При недоступности OpenBao используется только ограниченный по времени кэш; бесконечное продолжение с ранее прочитанными секретами запрещено.

Новые блоки не выдаются при занятости узла, несовместимой версии, потере heartbeat/mount, недостатке свободного и зарезервированного места, CPU >85%, RAM >90%, интенсивных ошибках либо достижении заданных порогов диска и сети. Быстрые узлы естественно запрашивают блоки чаще. Задания чередуются по времени последней выдачи.

## Границы проверенного профиля

Локальные контейнеры подтверждают прикладной протокол, параллелизм и восстановление. Они разделяют ядро, системные счётчики и локальный диск; это не измерение трёх независимых серверов, NFS `krb5p`, изоляции Kerberos или пропускной способности реального NAS. Для этих свойств предусмотрены Ansible и отдельная программа приёмки.
