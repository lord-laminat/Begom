# Контракты первой поставки

Машиночитаемое описание: [OpenAPI 3.1](openapi.json). Типы сообщений находятся в `internal/model/model.go`, обработчики — в `internal/coordinator`. Генератор и проверка покрытия маршрутов — `tools/openapi`. Все URL ниже относительны к соответствующему серверу.

## Версия, аутентификация и повтор

Публичный HTTPS обслуживает интерфейс и API пользователя. mTLS API агентов слушает отдельный порт 8444. `API-Version: 1` поддерживается; отсутствие заголовка означает версию 1, другое значение даёт HTTP 426. Совместимость агента проверяется при регистрации: API `1`, приложение `1.0.0`. Несовместимый агент не получает блок.

Пользователь входит через `POST /api/auth/login` с `username/password`. Ответ содержит пользователя и `csrf_token`; cookie сессии — Secure, HttpOnly, SameSite=Strict. Изменения требуют cookie, `X-CSRF-Token` и проверенного Origin. Роли: `administrator`, `operator`, `viewer`. Создание задания доступно оператору, управление существующим — при ACL `manage`, просмотр и выдача файла — при `view` либо `manage`. Администратор имеет доступ ко всем объектам. Недоступный объект обычно возвращает 404, чтобы не раскрывать его существование.

Агент предъявляет проверенную CA цепочку с URI `spiffe://begom/worker/WORKER`. URI должен совпадать с `workerId`. В регистрацию передаются `worker_id`, `session_id`, `version`, `api_version`, `source_id`, `storage_root`. Остальные запросы, включая WSS, требуют `Agent-Session` с подтверждённым `session_id`. Одновременное владение регистрацией запрещено; новая сессия ждёт утраты heartbeat старой. Отзыв serial проверяется и на существующем control-соединении.

Изменяющие операции, кроме login/logout, требуют `Idempotency-Key` длиной 1–200. Область ключа: субъект + HTTP method + path. SQL хранит SHA-256 **исходных байтов тела**, статус и подтверждённый JSON-ответ. Тот же ключ с теми же байтами возвращает сохранённый результат; другое тело — 409 `idempotency_conflict`. Для повтора после сетевого сбоя сохраняйте ключ и сериализованное тело, включая пробелы. Повтор подтверждённого отчёта возвращается и после истечения аренды, если текущая регистрация ещё действительна. Неподтверждённая операция может быть выполнена заново после отката транзакции.

Тело ограничено 2 МиБ. Неизвестные поля и второй JSON-объект отклоняются. Идентификаторы внешнего каталога и границы диапазона передаются десятичными строками `0..18446744073709551615`. Сервер также принимает целочисленную JSON-лексему без экспоненты; клиентам рекомендуется строка. UUID/короткий канонический ID хранится отдельно от числового ID. Размеры/счётчики не используются для вычисления границ.

## Задания и результаты

`POST /api/jobs` принимает `range_text` **либо** `from/to`, `worker_ids` и параметры `JobConfig`. Формы диапазона: пустая строка, `N`, `[A,B]`, `[A,]`; границы включаются. `stop_conditions.max_items` формирует эффективный диапазон. Блоки размером 1–10000 создаются по спросу. Ответ 201: `job_id`, `run_id`, `state`, `range`, `config_version`, нормализованный `config`.

Жизненный цикл: `created → validating → running`; `pause → pausing → paused`; `stop → stopping → stopped`; исчерпание → `completed`; невозможность продолжить → `failed`. При доступном сервере `validating` может завершиться в одной транзакции. `resume` из paused/stopped/failed создаёт новую `run_id`. Завершённый проход не возобновляется без явного выбора ошибок; для нового прохода создаётся задание. Пауза заканчивает начатые ID и возвращает не начатую часть блока.

`PATCH /api/jobs/ID/config` заменяет нормализуемую конфигурацию. Исходные границы и `max_items` неизменяемы. Версия увеличивается; потоки, серверы, ограничения, условия времени и повторы применяются к последующей работе. Отключённые от задания серверы теряют текущую аренду. Уменьшение параллелизма не подтверждает незавершённые операции.

Финальные результаты: `completed`, `not_found`, `forbidden`, `skipped`, `failed`. Промежуточные: `pending`, `checking`, `found`, `download_queued`, `downloading`, `retry_wait`, `rate_limited`, `cancelled`. `cancelled` сохраняет разрыв прогресса. 404 донора — `not_found`, 401/403 — `forbidden`, отсутствие опубликованного downloadLink — `skipped`; неизвестная схема и исчерпание повторов — `failed`. `sequence` не позволяет запоздалому промежуточному отчёту откатить новый. Только издатель подтверждает `completed`.

Контрольная точка блока/задания — первый ID без финального подтверждения. `null` означает исчерпание. Подтверждения последующих ID хранятся, но не скрывают пропуск. Дедупликация использует пару источник/канонический ID и только готовый каталог. Повторное использование файла возможно после разрешённого результата адаптера; новый `skipped` не превращается в completed из-за существующего файла.

Чтение и курсоры:

| Запрос | Порядок и параметры |
|---|---|
| `GET /api/jobs` | новые первыми; `limit` до 200; `before` — последний `job_id` предыдущей страницы; ответ `next_before` |
| `GET /api/jobs/ID/items` | внешний ID по возрастанию; `after` — исключительная десятичная граница; `status`, `limit` до 10000 |
| `GET /api/jobs/ID/events` | ID события по возрастанию; `after`, `limit` до 10000, `worker_id`, `status`, `from/to` RFC3339 |
| `GET /api/jobs/ID/export` | те же `status/after`, обязательный `format=json/csv`; все страницы без ограничения общей длины |
| `GET /api/workers/ID/metrics` | последнее ACL-фильтрованное измерение; история ОС хранится в Prometheus |
| `GET /api/audit` | администратор; `limit` до 10000, последние события по убыванию ID |

Проверяйте `complete/count` у JSON-экспорта, `incomplete_export` у CSV и trailer `X-Export-Complete`. Поток перечитывает авторизацию между порциями. Данные активно работающего задания могут меняться во время экспорта; мягкая пауза фиксирует набор. CSV защищён от формул электронной таблицы. Поля результата включают метаданные, статус, ошибку, размер, SHA-256, дату и сервер загрузки, логический путь и `file_id`.

## Аренда, C6 и публикация

`lease` возвращает `{lease:null}`, если сейчас нет подходящей работы. Иначе выдаёт `job_id/run_id/chunk_id/attempt_id`, границы, `next_id`, подтверждённые ID, время сервера, срок аренды и конфигурацию. Heartbeat продлевает только совпадающую действующую попытку; просроченная аренда не оживает. Блок выдаётся транзакционно; одна активная аренда на блок и одна на агент. `complete` разрешён только после закрытия всех пропусков; `fail` возвращает остаток. Старый attempt получает 409.

Каждый фактический HTTP-запрос начинается с `POST .../permits`: уникальный `request_uid`, класс `check/download` и ссылка аренды. Ответ 202: `state`, опциональный `permit`, `retry_after_ms`. Ожидание через GET по UID. Выданный permit содержит поколение, `not_before/expires_at`, отдельный `connection_id` и срок соединения. TTL допуска — 500 мс. Не используйте его повторно для redirect, retry, Range или другого URL. Продление connection разрешает продолжить один начатый ответ, но не открыть новый запрос. Освобождение передаёт `status`, `retry_after_ms`, `duration_ms`, `bytes` и сохраняет адаптацию до подтверждения.

SQL advisory lock и возобновляемый fence защищают единственное поколение. Новый координатор выдерживает drain, учитывая максимальный сохранённый горизонт квоты, прежние разрешения, соединения и погрешность часов. Агент отменяет работу при потере heartbeat/control, аренды, session, mount либо секрета за пределами кэша. Не обнуляйте таблицы квоты вручную.

Отчёт найденного разрешённого материала создаёт загрузку и SQL-резерв двух копий. `.part` принадлежит агенту и попытке. `POST .../downloads/ID/commit` передаёт stage, размер, SHA-256 и ссылку аренды; ответ 202 содержит публикацию. Издатель проверяет права и данные, создаёт собственный inode, повторно хеширует, переносит каталог атомарно и подтверждает SQL. GET публикации показывает `verifying`, `ready`, `failed` либо `orphan`. После сбоя между rename и SQL этап восстанавливается. Повреждённый каталог изымается из выдачи и помещается в карантин.

`GET /api/files/ID/content` выполняет проверку ACL, готовности каталога, mount и пути. Затем NGINX получает `X-Accel-Redirect`; наружу путь не служит разрешением доступа. Временные файлы никогда не обслуживаются. Range/If-Range реализуются NGINX; код 206 возможен после проверки доступа.

## WSS и управление узлами

`GET /api/events/stream` отправляет полный snapshot примерно раз в секунду: `server_time`, последние 200 доступных заданий, разрешённые серверы и измерения. Только администратор получает глобальные сведения C6/source. После разрыва интерфейс перечитывает `GET /api/snapshot`, затем подключается заново. Это поток актуального состояния, не журнал надёжной доставки; журнал читается HTTP с курсором. Авторизация проверяется в каждом цикле.

Агентский `.../control` отправляет раз в 250 мс время сервера, epoch, ready и карту chunk → attempt/state/expiry. Потеря права работы отменяет запросы; heartbeat остаётся подтверждением SQL.

Управление узлом — асинхронный `POST .../actions` с `check/start/stop/restart/install/update`, для обновления также `version`. Сначала сохраняется SQL intent, затем выполняется SSH с проверенным host key. Состояния доступны в actions: pending/running/succeeded/failed/outcome_unknown. После неопределённого исхода не повторяется рестарт автоматически.

Терминал: POST `.../ssh/sessions` выдаёт одноразовый ticket на 30 секунд. WSS `.../ssh/stream` сначала принимает `{"ticket":"..."}`, затем `{"command":"status","command_id":"уникальный ID"}`. Ответы содержат `output`; ticket и пароль не передаются в URL. Команды ограничены `help/status/resources/logs N/start/stop/restart`, вывод ограничен, срок 15 минут, idle 2 минуты. Обновление передаёт только подписанный пакет через отдельную операцию. SQL аудит включает создание/закрытие сессии и нормализованные команды.

## Ошибки и изменения схемы

Ошибка: `code`, безопасное `message`, `request_id`, опциональный `retry_after_ms`. 400 — синтаксис/ключ, 401 — вход, 403 — запрещённое действие/CSRF, 404 — отсутствующий либо недоступный объект, 409 — состояние/попытка/конфликт ключа, 413 — тело, 422 — параметры, 426 — версия, 429 — ограничение входа/очереди, 503 — зависимость/восстановление. На 409 stale_attempt/agent_session_lost работу надо отменить; на 503 допустим ограниченный повтор тем же ключом, пока действует право работы. Ошибки SQL/OpenBao не возвращают DSN и секреты.

Миграции 001–004: исходные таблицы/ограничения; восстановление/квота/sequence; идемпотентная обратная связь донора; сверка каталога. Они применяются по порядку под SQL lock, с проверкой checksum. Откат схемы автоматическим удалением данных не выполняется. До изменения API или поколения требуется проверить одновременно установленные версии; при этой поставке координатор и агент обновляются согласованно.
